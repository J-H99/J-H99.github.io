슬라이드별 노트

처음 감 잡기 · 4분

01. 클라우드 스토리지는 무엇인가

핵심 메시지: 내 컴퓨터가 아니라 인터넷 너머의 저장 공간을 빌려 쓰는 방식입니다.

  • 사진, 동영상, 백업 파일, 로그처럼 큰 데이터를 클라우드에 저장합니다.
  • 사용자는 인터넷을 통해 올리고, 내려받고, 공유합니다.
  • 중요한 질문은 어디에 저장되는가보다 누가, 언제, 어떻게 접근하는가입니다.

발표 팁: 첫 문장으로 말하면: 클라우드 스토리지는 서버실에 직접 디스크를 꽂지 않고 저장 공간을 서비스로 빌려 쓰는 것입니다.

출처/근거: AWS S3 User Guide; Google Cloud Storage docs

처음 감 잡기 · 4분

02. 왜 그냥 내 서버 디스크에 저장하지 않을까

핵심 메시지: 서비스가 커지면 디스크 관리가 개발보다 더 어려워질 수 있습니다.

  • 사용자가 많아지면 저장 공간을 계속 늘려야 합니다.
  • 서버가 고장 나도 파일이 사라지지 않아야 합니다.
  • 여러 지역의 사용자가 빠르게 접근하려면 위치와 네트워크도 중요합니다.

발표 팁: 작은 과제 서비스는 서버 디스크로도 충분합니다. 하지만 서비스가 커질수록 저장소 운영이 별도 일이 됩니다.

처음 감 잡기 · 4분

03. 우리 주변의 클라우드 스토리지

핵심 메시지: 이미 매일 쓰는 서비스 안에 클라우드 스토리지가 숨어 있습니다.

  • 프로필 사진, 게시글 이미지, 강의 녹화 영상은 보통 별도 저장소에 둡니다.
  • 휴대폰 사진 백업과 문서 공유도 같은 아이디어를 씁니다.
  • 앱 서버는 파일을 직접 들고 있기보다 저장 위치와 권한을 관리합니다.

발표 팁: 학생에게 익숙한 예시로 시작하면 좋습니다: 메신저 사진, 구글 드라이브, 유튜브 영상, LMS 과제 파일.

출처/근거: 강의 설명용 예시

처음 감 잡기 · 4분

04. 오늘은 올리고, 찾고, 공유하고, 지우는 흐름으로 본다

핵심 메시지: 클라우드 스토리지는 어려운 용어보다 파일의 생애 주기로 이해하면 쉽습니다.

  • 업로드: 누가 어떤 파일을 올리는가.
  • 보관: 어디에, 어떤 이름으로, 얼마나 오래 둘 것인가.
  • 접근: 누가 볼 수 있고 어떻게 공유할 것인가.
  • 정리: 비용과 개인정보 때문에 언제 지울 것인가.

발표 팁: 이 강연의 핵심 흐름은 upload, store, access, delete입니다. 뒤의 모든 개념을 여기에 붙여 설명합니다.

처음 감 잡기 · 4분

05. 비유로 보면 창고와 도서관 사이에 있다

핵심 메시지: 그냥 박스만 쌓는 창고도 아니고, 검색과 규칙이 있는 보관 시스템입니다.

  • 창고처럼 많은 물건을 오래 보관합니다.
  • 도서관처럼 이름표, 분류, 대출 규칙이 필요합니다.
  • 금고처럼 아무나 열 수 없게 권한과 기록을 남깁니다.

발표 팁: 처음 듣는 학생에게는 인터넷 창고 + 이름표 + 출입 권한이라는 비유가 가장 잘 먹힙니다.

출처/근거: 강의 설명용 비유

핵심 개념 · 4분

06. 파일과 객체는 비슷하지만 같은 말은 아니다

핵심 메시지: 객체 스토리지는 파일 시스템보다 단순한 대신 대규모 보관에 강합니다.

  • 파일 시스템은 폴더 안 파일처럼 생각합니다.
  • 객체 스토리지는 이름표가 붙은 큰 데이터 조각을 보관한다고 보면 됩니다.
  • 객체에는 내용뿐 아니라 파일 종류, 만든 사람, 만료일 같은 정보도 붙일 수 있습니다.

발표 팁: 너무 깊게 들어가지 말고, 객체는 데이터 + 이름 + 설명이라고 잡으면 충분합니다.

출처/근거: AWS S3 User Guide; Google Cloud Storage docs

핵심 개념 · 4분

07. 버킷은 큰 보관함, 객체는 그 안의 물건이다

핵심 메시지: 버킷은 저장 공간의 큰 경계이고, 객체는 실제 저장되는 하나하나의 데이터입니다.

  • 버킷에는 많은 객체가 들어갑니다.
  • 버킷마다 권한, 지역, 수명주기 규칙을 다르게 둘 수 있습니다.
  • 프로젝트나 서비스 단위로 버킷을 나누면 관리가 쉬워집니다.

발표 팁: 버킷을 폴더 하나로 오해하기 쉽지만, 실무에서는 정책과 비용의 경계로 보는 편이 좋습니다.

출처/근거: AWS S3 User Guide

핵심 개념 · 4분

08. 객체 이름은 폴더처럼 보이지만 사실 주소표다

핵심 메시지: photos/2026/cat.jpg 같은 이름은 폴더라기보다 긴 주소라고 이해하면 쉽습니다.

  • 슬래시가 들어가면 폴더처럼 보이지만, 객체 스토리지에서는 이름의 일부입니다.
  • 이름 규칙을 잘 잡으면 나중에 찾고 지우고 비용을 나누기 쉽습니다.
  • 이름 안에 주민번호, 이메일 같은 개인정보를 넣는 것은 피해야 합니다.

발표 팁: 좋은 객체 이름은 예쁜 이름이 아니라 나중에 관리하기 쉬운 이름입니다.

출처/근거: 강의 설명용 예시

핵심 개념 · 4분

09. 메타데이터는 파일에 붙이는 설명 스티커다

핵심 메시지: 파일 내용은 그대로 두고, 파일을 어떻게 다룰지 알려주는 정보입니다.

  • Content-Type은 브라우저가 이미지인지 PDF인지 알게 해줍니다.
  • owner, team, purpose 같은 정보는 나중에 비용과 권한을 나누는 데 도움 됩니다.
  • 만료일이나 보관 기간을 태그로 붙이면 자동 정리에 쓸 수 있습니다.

발표 팁: 메타데이터는 처음엔 사소해 보이지만, 파일이 수백만 개가 되면 거의 유일한 길잡이가 됩니다.

출처/근거: AWS S3 metadata docs; Google Cloud Storage docs

핵심 개념 · 4분

10. 스토리지에는 객체, 파일, 블록 방식이 있다

핵심 메시지: 이름은 어렵지만 어떻게 읽고 쓰는가로 나누면 됩니다.

  • 객체 스토리지는 이미지, 영상, 백업, 로그처럼 큰 덩어리 보관에 많이 씁니다.
  • 파일 스토리지는 여러 서버가 같은 폴더를 함께 쓰는 느낌입니다.
  • 블록 스토리지는 서버에 붙이는 디스크에 가깝고 데이터베이스 디스크에 자주 쓰입니다.

발표 팁: 초심자에게는 외울 필요 없습니다. 사진 보관은 객체, 공유 폴더는 파일, 서버 디스크는 블록 정도면 충분합니다.

출처/근거: 강의 설명용 정리

서비스 선택 · 4분

11. AWS S3, Azure Blob, Google Cloud Storage는 같은 범주의 서비스다

핵심 메시지: 회사마다 이름은 다르지만 큰 아이디어는 비슷합니다.

  • AWS에서는 S3라는 이름을 많이 듣습니다.
  • Azure에서는 Blob Storage, Google Cloud에서는 Cloud Storage라고 부릅니다.
  • 처음에는 이름보다 버킷, 객체, 권한, 비용이라는 공통 개념을 잡는 것이 중요합니다.

발표 팁: 벤더 이름을 다 외우는 강연이 아닙니다. 같은 질문을 다른 서비스에 적용하는 감각을 만드는 강연입니다.

출처/근거: AWS S3; Azure Blob; Google Cloud Storage docs

서비스 선택 · 4분

12. 자주 쓰는 파일과 오래 보관하는 파일은 다르게 둔다

핵심 메시지: 스토리지 클래스는 파일의 온도를 고르는 일입니다.

  • 매일 보는 이미지는 바로 읽을 수 있는 곳에 둡니다.
  • 가끔 보는 백업은 더 싼 곳에 둘 수 있습니다.
  • 거의 안 보는 자료는 싸게 보관할 수 있지만 꺼내는 데 시간이 걸릴 수 있습니다.

발표 팁: 학생에게는 hot, cool, archive를 냉장고 비유로 설명하면 쉽습니다.

출처/근거: Azure access tiers; Google Cloud storage classes

서비스 선택 · 4분

13. 오래된 파일은 자동으로 옮기거나 지울 수 있다

핵심 메시지: 수명주기 정책은 파일 정리 규칙을 자동화하는 기능입니다.

  • 30일 지난 임시 파일 삭제처럼 단순한 규칙부터 시작할 수 있습니다.
  • 90일 지난 로그를 더 싼 저장 공간으로 옮길 수 있습니다.
  • 자동화 전에는 작은 범위에서 먼저 테스트해야 합니다.

발표 팁: 클라우드 스토리지는 저장만 하는 곳이 아니라 정리 규칙까지 가질 수 있습니다.

출처/근거: Google Cloud lifecycle docs; AWS S3 Lifecycle

서비스 선택 · 4분

14. 어느 지역에 저장할지도 선택이다

핵심 메시지: 파일이 어디에 있느냐는 속도, 법, 장애 대응과 연결됩니다.

  • 한국 사용자에게 너무 먼 지역의 파일은 느릴 수 있습니다.
  • 일부 데이터는 특정 국가나 지역 밖으로 나가면 안 될 수 있습니다.
  • 여러 지역에 복사하면 장애에는 강하지만 비용과 복잡도가 올라갑니다.

발표 팁: 처음에는 사용자와 가까운 곳, 규정에 맞는 곳, 장애에 버틸 수 있는 곳 정도로 설명하면 충분합니다.

출처/근거: Azure redundancy docs; Google Cloud Storage docs

사용 예시 · 4분

15. 웹 서비스에서 파일 업로드는 보통 이렇게 흐른다

핵심 메시지: 앱 서버가 파일을 다 들고 있기보다 클라우드 저장소에 맡깁니다.

  • 사용자가 업로드 버튼을 누르면 앱 서버가 업로드 허가를 확인합니다.
  • 파일은 클라우드 스토리지로 올라갑니다.
  • 앱 서버는 DB에 파일 이름, 주인, 상태 같은 정보를 저장합니다.

발표 팁: 초심자에게는 presigned URL 같은 단어보다 서버는 허가증을 주고, 파일은 창고로 간다고 말하면 됩니다.

출처/근거: AWS S3 presigned URL docs

사용 예시 · 4분

16. 다운로드와 공유 링크는 권한을 담은 문이다

핵심 메시지: 링크 하나를 만들 때도 누가 언제까지 볼 수 있는지 정해야 합니다.

  • 공개 파일은 누구나 볼 수 있지만 위험합니다.
  • 비공개 파일은 로그인한 사용자나 임시 링크로만 접근하게 할 수 있습니다.
  • 임시 링크는 시간이 지나면 자동으로 만료되게 만들 수 있습니다.

발표 팁: 학생들이 익숙한 구글 드라이브 공유 링크를 떠올리게 하면 바로 이해합니다.

출처/근거: AWS S3 presigned URL docs

사용 예시 · 4분

17. 이미지 서비스는 원본과 썸네일을 따로 생각한다

19. 동영상과 이미지가 빠른 이유에는 CDN이 있다

핵심 메시지: 자주 보는 파일은 사용자 가까운 곳에 복사해두면 빠릅니다.

발표 팁: CDN은 오늘 깊게 배우지 않고 사용자 가까운 복사본 정도로만 잡습니다.

20. 기본은 비공개여야 한다

21. 권한은 문 열쇠를 나눠주는 일이다

23. 암호화는 잠금장치, 키 관리는 열쇠 관리다

24. 비용은 저장 용량만 보면 안 된다

핵심 메시지: 클라우드 스토리지 비용은 보관료, 요청 수, 다운로드, 복구가 함께 만듭니다.

  • 파일을 많이 저장하면 용량 비용이 듭니다.
  • 파일을 자주 읽고 쓰면 요청 비용이 늘 수 있습니다.
  • 인터넷으로 많이 내려보내면 전송 비용이 커질 수 있습니다.

발표 팁: 가격 숫자는 계속 바뀌므로 외우지 않습니다. 대신 비용 항목을 빠뜨리지 않는 습관을 만듭니다.

25. 지우지 않는 파일은 언젠가 비용과 위험이 된다

발표 팁: 학생 프로젝트에도 적용 가능합니다. 업로드 테스트 파일을 자동으로 지우는 것부터 시작하면 됩니다.

30. 마지막으로 이 10가지만 기억하자
